# Running the Code and Checking the Paper Results

This directory contains the final reproduction package for **Evaluating Event Normalization and Inferred Patient Replica Weighting for Federated Clinical-Event Learning: A Reproducible Synthetic Evaluation**. Input data are included; you do not need to regenerate Synthea data.

## 1. Running the Code

Use Python 3.12 on either Windows or Linux. The experiment code uses `pathlib` and does not depend on OS-specific input or output paths. Run the following commands from this package directory to install the pinned dependencies and execute all experiments.

### Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements_synthetic_v3.txt
bash RUN_FINAL_EXPERIMENT.sh new_reproduction_output
```

To specify a Python interpreter explicitly:

```bash
PYTHON=/absolute/path/to/venv/bin/python bash RUN_FINAL_EXPERIMENT.sh new_reproduction_output
```

### Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements_synthetic_v3.txt
$env:Path = (Join-Path $PWD '.venv\Scripts') + ';' + $env:Path
powershell -ExecutionPolicy Bypass -File .\RUN_FINAL_EXPERIMENT.ps1 -OutputDir new_reproduction_output
```

The PowerShell script invokes the `python` executable on `PATH`. The commands above put the virtual environment first on `PATH`; alternatively, activate the environment before running the script.

The output directory must be absent or empty. Relative paths are resolved against this package directory. If `new_reproduction_output` already contains saved results, specify another empty directory and use that directory in the verification commands below.

The scripts run input verification, 14 regression tests, experiments for 3 missingness scenarios and 5 seeds, artifact auditing, figure generation, inferred-cluster diagnostics, oracle-weight diagnostics, the three post-hoc analyses reported in Table 9, and the included numerical result checker. Any failed step stops execution. The message `Completed final-paper reproduction` appears only after all steps succeed. Full output occupies approximately 2.82 GB, excluding the temporary files used by the supplemental analysis.

## 2. Checking Agreement with the Paper

### Step 1: Confirm Experiment Completion and Audit Success

All 8 input CSV files should report `OK`, all 14 tests should pass, and the final step should print `PASS`. After execution, check these fields in `new_reproduction_output/integrity_audit.json`:

```json
{
  "passed": true,
  "runs_checked": 15,
  "sites_checked": 75,
  "input_csv_hashes_checked": 8
}
```

The actual file contains additional audit information. A successful audit confirms consistency of the inputs, generated artifacts, labels, grouped patient splits, and recorded metrics. Numerical agreement with the paper must also be checked as described below.

### Step 2: Compare Outputs with the Paper Tables and Figures

All paths below are relative to `new_reproduction_output/`. The scenarios `missing_00`, `missing_10`, and `missing_30` correspond to 0%, 10%, and 30% missingness.

| Paper result | Output file and field |
|---|---|
| Table 1: Preprocessing modes | The mode definitions are in the paper and `ALIGNMENT_STUDY_PROTOCOL_V3.md`; no numerical output file is required. |
| Table 2: Site-macro FedAvg classification metrics | Each scenario's `summary.json`: `summary.federated_metrics.<mode>.fedavg.<metric>` |
| Table 3: Paired differences, weighting minus normalization | `study_summary.json`: `paired_alignment_aware_fedavg_minus_control.<scenario>.normalized_events` |
| Table 4: All methods at 10% missingness | `missing_10/summary.json`: `summary.federated_metrics.<mode>.<method>.<metric>` |
| Table 5: Alignment and duplicate detection | Each scenario's `summary.json`: `summary.entity_alignment` and `summary.duplicate_detection` |
| Table 6: Communication payload | Each scenario's `seed_*/federated_results.json`: `modes.<mode>.methods.fedavg.communication_bytes`; average over five seeds and divide by 1,000,000 for MB |
| Table 7: Final inferred-cluster diagnostics | `inferred_cluster_audit/cluster_audit_summary.json`: `summary` |
| Table 8: Oracle weights minus inferred weights | `oracle_weight_diagnostic/summary.json`: `summary` |
| Table 9: Source-patient and sensitivity analyses | `supplemental_sensitivity/*.json`: generated by `supplemental_sensitivity.py` for the baseline source-patient evaluation, lower-overlap condition, and 80-round condition. |
| Figure 1: FedAvg classification metrics | `figures/fedavg_missingness.png` (SVG and PDF are also available) |
| Figure 2: Communication payload | `figures/fedavg_payload.png` (SVG and PDF are also available) |

Mode keys are `raw`, `aligned`, `normalized_events`, and `alignment_aware`. Method keys are `local_only`, `fedavg`, `fedprox`, and `centralized_upper_bound`. Metrics `f1`, `auroc`, and `auprc` correspond to F1, AUROC, and average precision (AP).

The paper's mean and standard deviation correspond to `mean` and `std`; 95% bootstrap intervals correspond to `bootstrap_95_ci`. Classification metrics are averaged equally across sites before aggregation over the five seeds. Compare values after rounding to the decimal precision used in the paper; a single seed cannot replace the aggregate result.

### Step 3: Run the Included Result Checker

The package includes `check_results.py`. After reproduction, run:

```bash
# Linux
python3 -B check_results.py --study-dir new_reproduction_output

# Windows
python -B check_results.py --study-dir new_reproduction_output
```

Set `--study-dir` to the directory containing the results you want to check. Relative paths are resolved against this package directory. Successful verification prints `PASS`. Missing files or mismatched values produce `FAIL` and a nonzero exit code.

This checker covers the three sets of key metrics at 10% missingness reported in the abstract. Compare all other tables and figures using the mapping above. Do not compare entire JSON or image files by hash to judge numerical reproduction: timestamps, paths, platform information, and image metadata can differ between environments.

## 3. Code and Archive

This package is intended to be archived as a versioned Zenodo release. The
version-specific Zenodo DOI is intentionally not embedded in this archive:
Zenodo assigns or confirms the DOI when a release is published, and a later
release may have a different version DOI. Use the final DOI recorded in the
accompanying manuscript and in the Zenodo record metadata. The SHA-256
manifest in this package identifies the exact contents of this downloaded
archive independently of the DOI.

The package contains selected Synthea synthetic inputs and executable
reproduction code; it does not contain real patient records or pre-generated
result directories.

## 4. Checking the Published Package

The package includes the selected Synthea synthetic input CSV files, source code, tests, and the scripts needed to regenerate site files, experiment outputs, figures, diagnostics, and Table 9. Generated result directories and supplemental summary JSON files are intentionally not included in this source package; they are reproducible outputs generated by `supplemental_sensitivity.py`.

The current `PACKAGE_SHA256SUMS.txt` lists the 36 files in this package (the checksum file itself is excluded). The portable Python verifier works on Windows, Linux and macOS and requires no external checksum utility:

```text
python verify_package_hashes.py
```

On Linux or macOS with GNU coreutils, the equivalent command is:

```bash
sha256sum -c PACKAGE_SHA256SUMS.txt
```

`sha256sum -c` is not a standard Windows PowerShell command. On Windows, use `python verify_package_hashes.py` from PowerShell instead.

Every listed file should report `OK`. This verifies the downloaded package contents; it does not replace running the experiment and checking its numerical results.

## 4. Cohort B replication (v1.1.0)

Section 4.9 and Table 10 of the manuscript report an independent replication on a second
Synthea cohort (patient and clinician seeds 20261012; 1,152 patients; 269 positive; 78,092
retained events). Its selected inputs, scenario summaries and per-seed results are under
`cohort_b/`; see `cohort_b/README_COHORT_B.md` for provenance, exact commands and the
mapping between files and Table 10.

The experiment code and the primary cohort in `data/synthea_input/` are unchanged from
v1.0.0. The cohort B analysis uses the same `run_alignment_study.py`, experiment seeds and
evaluation rules as the primary cohort.
